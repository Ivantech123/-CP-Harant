# Requirements Document

## Introduction

Harant MCP Server - это сервер, реализующий Model Context Protocol (MCP) для интеграции юридического портала Harant (https://harant.ru/) с популярными AI моделями. Сервер предоставляет AI моделям доступ к информации о юристах, их профилях, специализациях и контактным данным через стандартизированный протокол MCP.

## Glossary

- **MCP_Server**: Сервер, реализующий Model Context Protocol для взаимодействия с AI моделями
- **Harant_Portal**: Юридический портал по адресу https://harant.ru/
- **Lawyer_Profile**: Профиль юриста на портале Harant, содержащий информацию о специализации, опыте и контактах
- **AI_Model**: Языковая модель искусственного интеллекта (Claude, GPT, Gemini и др.)
- **MCP_Tool**: Функция, предоставляемая MCP сервером для выполнения AI моделью
- **Search_Query**: Поисковый запрос для поиска юристов по критериям
- **Profile_URL**: URL адрес профиля юриста на портале Harant
- **Lawyer_Data**: Структурированные данные о юристе (имя, специализация, город, контакты)

## Requirements

### Requirement 1: Поиск юристов

**User Story:** Как пользователь AI модели, я хочу искать юристов по различным критериям, чтобы найти подходящего специалиста для моей задачи

#### Acceptance Criteria

1. WHEN AI модель запрашивает поиск юристов с указанием города, THE MCP_Server SHALL вернуть список юристов из указанного города
2. WHEN AI модель запрашивает поиск юристов с указанием специализации, THE MCP_Server SHALL вернуть список юристов с указанной специализацией
3. WHEN AI модель запрашивает поиск юристов с указанием имени, THE MCP_Server SHALL вернуть список юристов, чьи имена соответствуют запросу
4. WHEN поисковый запрос не содержит результатов, THE MCP_Server SHALL вернуть пустой список с соответствующим сообщением
5. WHEN поисковый запрос содержит некорректные параметры, THE MCP_Server SHALL вернуть описательное сообщение об ошибке

### Requirement 2: Получение профиля юриста

**User Story:** Как пользователь AI модели, я хочу получать детальную информацию о конкретном юристе, чтобы оценить его квалификацию и опыт

#### Acceptance Criteria

1. WHEN AI модель запрашивает профиль юриста по Profile_URL, THE MCP_Server SHALL извлечь и вернуть полную информацию о юристе
2. THE Lawyer_Data SHALL включать имя юриста, город, специализацию, опыт работы и контактную информацию
3. WHEN Profile_URL указывает на несуществующий профиль, THE MCP_Server SHALL вернуть сообщение об ошибке с кодом 404
4. WHEN Profile_URL имеет некорректный формат, THE MCP_Server SHALL вернуть описательное сообщение об ошибке валидации
5. THE MCP_Server SHALL извлекать данные непосредственно с Harant_Portal в режиме реального времени

### Requirement 3: Парсинг HTML страниц портала

**User Story:** Как разработчик, я хочу надежно извлекать данные со страниц Harant портала, чтобы предоставлять актуальную информацию AI моделям

#### Acceptance Criteria

1. WHEN MCP_Server получает HTML страницу профиля юриста, THE HTML_Parser SHALL извлечь структурированные данные о юристе
2. THE HTML_Parser SHALL корректно обрабатывать кириллические символы в именах и описаниях
3. WHEN HTML структура страницы изменяется, THE HTML_Parser SHALL логировать предупреждение о несоответствии структуры
4. THE HTML_Parser SHALL извлекать все доступные поля профиля (имя, город, специализация, опыт, контакты, рейтинг)
5. WHEN обязательное поле отсутствует на странице, THE HTML_Parser SHALL вернуть ошибку с указанием отсутствующего поля

### Requirement 4: Форматирование данных для AI моделей

**User Story:** Как AI модель, я хочу получать данные в структурированном формате, чтобы эффективно их обрабатывать и представлять пользователю

#### Acceptance Criteria

1. THE MCP_Server SHALL возвращать данные в формате JSON
2. THE JSON_Schema SHALL быть валидной и соответствовать спецификации MCP
3. WHEN данные содержат специальные символы, THE Data_Formatter SHALL корректно экранировать их для JSON
4. THE Data_Formatter SHALL включать метаданные о времени получения данных и источнике
5. FOR ALL валидных Lawyer_Data объектов, сериализация в JSON и десериализация обратно SHALL производить эквивалентный объект (round-trip property)

### Requirement 5: Интеграция с MCP протоколом

**User Story:** Как разработчик AI приложения, я хочу использовать стандартный MCP протокол, чтобы легко интегрировать сервер с различными AI моделями

#### Acceptance Criteria

1. THE MCP_Server SHALL реализовывать спецификацию Model Context Protocol версии 1.0 или выше
2. THE MCP_Server SHALL регистрировать все доступные MCP_Tool при инициализации
3. WHEN AI модель запрашивает список доступных инструментов, THE MCP_Server SHALL вернуть описание всех MCP_Tool с их параметрами и схемами
4. THE MCP_Server SHALL поддерживать стандартные методы MCP: initialize, tools/list, tools/call
5. WHEN происходит ошибка выполнения инструмента, THE MCP_Server SHALL возвращать ошибку в формате, соответствующем MCP спецификации

### Requirement 6: Обработка ошибок и устойчивость

**User Story:** Как пользователь системы, я хочу получать понятные сообщения об ошибках, чтобы понимать, что пошло не так и как это исправить

#### Acceptance Criteria

1. WHEN Harant_Portal недоступен, THE MCP_Server SHALL вернуть ошибку с указанием проблемы соединения и временем повторной попытки
2. WHEN запрос к Harant_Portal превышает таймаут 30 секунд, THE MCP_Server SHALL прервать запрос и вернуть ошибку таймаута
3. WHEN происходит сетевая ошибка, THE MCP_Server SHALL выполнить до 3 повторных попыток с экспоненциальной задержкой
4. THE MCP_Server SHALL логировать все ошибки с уровнем severity и stack trace
5. WHEN возникает критическая ошибка, THE MCP_Server SHALL продолжать работу и обрабатывать последующие запросы

### Requirement 7: Кэширование данных

**User Story:** Как администратор системы, я хочу минимизировать нагрузку на Harant портал, чтобы обеспечить стабильную работу и быстрые ответы

#### Acceptance Criteria

1. WHEN MCP_Server получает запрос на данные юриста, THE Cache_Manager SHALL проверить наличие актуальных данных в кэше
2. THE Cache_Manager SHALL хранить данные профилей юристов в течение 24 часов
3. WHEN данные в кэше устарели, THE Cache_Manager SHALL запросить свежие данные с Harant_Portal
4. THE Cache_Manager SHALL использовать Profile_URL в качестве ключа кэша
5. WHERE кэширование включено, THE MCP_Server SHALL возвращать данные из кэша в течение 100 миллисекунд

### Requirement 8: Конфигурация сервера

**User Story:** Как администратор, я хочу настраивать параметры сервера, чтобы адаптировать его под конкретные требования развертывания

#### Acceptance Criteria

1. THE MCP_Server SHALL загружать конфигурацию из файла при запуске
2. THE Configuration SHALL включать параметры: базовый URL портала, таймауты, настройки кэша, уровень логирования
3. WHEN файл конфигурации отсутствует, THE MCP_Server SHALL использовать значения по умолчанию
4. WHEN параметр конфигурации имеет некорректное значение, THE MCP_Server SHALL вернуть ошибку валидации с описанием проблемы
5. THE Configuration_Parser SHALL валидировать все параметры перед применением

### Requirement 9: Логирование и мониторинг

**User Story:** Как администратор системы, я хочу отслеживать работу сервера, чтобы выявлять проблемы и оптимизировать производительность

#### Acceptance Criteria

1. THE MCP_Server SHALL логировать все входящие запросы с временными метками и параметрами
2. THE MCP_Server SHALL логировать время выполнения каждого запроса
3. WHEN запрос выполняется дольше 5 секунд, THE MCP_Server SHALL логировать предупреждение о медленном выполнении
4. THE Logger SHALL поддерживать уровни логирования: DEBUG, INFO, WARNING, ERROR, CRITICAL
5. THE MCP_Server SHALL записывать логи в файл и выводить в консоль одновременно

### Requirement 10: Совместимость с популярными AI моделями

**User Story:** Как пользователь различных AI платформ, я хочу использовать один MCP сервер с разными моделями, чтобы не настраивать интеграцию для каждой модели отдельно

#### Acceptance Criteria

1. THE MCP_Server SHALL быть совместимым с Claude (Anthropic)
2. THE MCP_Server SHALL быть совместимым с ChatGPT (OpenAI)
3. THE MCP_Server SHALL быть совместимым с Gemini (Google)
4. THE MCP_Server SHALL предоставлять документацию по подключению для каждой поддерживаемой AI_Model
5. WHEN AI_Model отправляет запрос в формате MCP, THE MCP_Server SHALL корректно обработать запрос независимо от источника
